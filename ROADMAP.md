# 16-Week Roadmap

The subjects run in parallel. Do not finish one entire subject before starting the next.

| Weeks | C++ / DSA | Systems / Networking | Cloud / Platform | AI / Design |
|---|---|---|---|---|
| 1–2 | Memory, ownership, arrays, strings, hashing | Linux basics, processes and threads | AWS fundamentals | ML/LLM concepts, transformers and embeddings |
| 3–4 | STL, OOP, linked lists, stacks, queues | Mutexes, races, GDB, sanitizers | AWS core services overview | Inference lifecycle, LLM application basics |
| 5–6 | Copy/move, templates, trees, heaps | Concurrency, virtual memory, profiling | Docker, EC2, S3, networking, monitoring | Embeddings, chunking, vector search |
| 7–8 | Async, futures, graph basics | IPC, TCP/UDP, sockets, Linux internals | Dockerised services, first deployment | RAG prototype and evaluation basics |
| 9–10 | Graphs and DP foundations | Distributed systems, reliability | SQS/SNS, databases, Kubernetes basics | RAG evaluation, model serving |
| 11–12 | Mixed DSA and timed practice | Replication, partitioning, failure recovery | Helm, probes, autoscaling, deployment | GPU memory, batching, quantisation |
| 13–14 | Advanced C++, implementation and debugging | LLD/HLD, networking and troubleshooting | Kubernetes and cloud troubleshooting | AI serving architecture and scaling |
| 15–16 | Mock coding rounds and revision | Senior-level systems/design interviews | Project walkthroughs | AI project walkthrough and applications |

## Weekly rhythm

- Monday–Thursday: learn and implement new concepts.
- Friday: debugging, harder exercises and catch-up.
- Saturday: timed coding and project work.
- Sunday: revision, assessment and next-week planning.

## Daily three-hour allocation

- 60 min: C++ / systems learning and implementation.
- 45 min: DSA.
- 35 min: AWS, platform or AI infrastructure.
- 30 min: project or system design.
- 10 min: recall without notes.

The allocation can shift within a week, but keep C++ and DSA continuous.
